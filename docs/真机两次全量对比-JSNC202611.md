### 3.3 为什么 F1 会涨 4.4pt：19 条"JSON 失败"消失了

| 端侧指标 | 11-03 | 11-11 |
|---|---|---|
| JSON 输出合法率 | **89.2%**（157/176） | **100%**（176/176） |
| 未产出意图（转云） | **19 条**（10.8%） | **0 条** |

新增的 22 道"变对"里，大量在 11-03 是 `pred_intent = None`（模型没吐出合法 JSON，直接转云）。
根因指向 **E1（prompt 3373→2373 字符）**：端侧小模型在长 prompt 下更容易输出坏 JSON，prompt 一短，格式就稳了。
**这是端侧特有收益，PC 上不明显**（PC 的 JSON 失败基数小）。

## 八、局限与未测项

1. **总耗时不可比**：11-03 四子集 60 分 25 秒；11-11 因 mask 首轮 503 重跑，实为 33 分钟（intent+faq+tool）+ 29 分钟（mask 单跑），受网络抖动影响，**不能用来论证快慢**；
2. **逐条耗时未记录**：`raw.jsonl` 未存 timings，延迟需单独 benchmark；
3. **X1 量化未上机**：手机上的 Q4 文件未推送，本次仍是 Q8_0；Q4 的省内存/等质量结论仅在 PC 验证过；
4. **样本量限制**：意图每类 5 条，单条 = 20pt，类级召回变化只能看趋势，不能算显著性。
