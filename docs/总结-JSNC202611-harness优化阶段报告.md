## 一、一页结论

**做了什么**：在不改模型权重的前提下，通过提示词、注册表、代码逻辑三层改造，
把端侧智能体在四个评测子集上的表现推到"大部分达标"，并用 33 条可追溯实验记录下每一步的
效果、代价与失败原因。

**当前成绩（双模型，PC 环境）**：

| 指标 | 阈值 | 1.7B-Q8 | 4B-2507-Q4 | 状态 |
|---|---|---|---|---|
| 脱敏 精度 P | ≥0.90 | **0.961** | **0.938** | ✅ 双模型达标 |
| 脱敏 召回 R | ≥0.95 | **0.961** | **0.957** | ✅ 双模型达标 |
| 工具 A 调用成功 | ≥0.80 | **1.000** | **1.000** | ✅ |
| 工具 B 缺参追问 | ≥0.80 | 0.875 | **1.000** | ✅ |
| 工具 C 安全底线 | 100% | **1.000** | **1.000** | ✅ |
| 工具 D 域外路由 | — | **1.000** | **1.000** | ✅ |
| 意图 OOS 拒识 | ≥0.85 | **0.923** | **0.962** | ✅ |
| 意图 准确率 | ≥0.85 | **0.881** | **0.915** | ✅ |
| 意图 macro-F1 | ≥0.90 | 0.866 | **0.899** | ⚠️ 4B 差 0.1pt |
| FAQ 信息点命中 | ≥0.80 | 0.663 | **0.827** | ✅ 4B 达标（v3 口径） |

> **FAQ 口径说明**：表中为**判分器 v3（证据化复核）**口径。旧口径 v2 给出 0.606（1.7B）/0.788（4B），
> v3 修正了启发式的系统性偏严（同义改写被判 miss），真实值高 4-8pt。v2 仍为默认判分（确定性、可复现），
> v3 用于能力评估与对外汇报。
>
> **intent 0.899 的旁证**：换成同一模型的 **Q8_0** 量化后，intent macro-F1 = **0.9084**（名义过阈），
> faq 持平（0.827）。结合同配置重跑 ±3pt 的波动（§9），这 0.1pt 差距确认是噪声而非能力缺口；
> 但量产仍建议 Q4（省 40% 内存，质量代价在噪声内）——详见 §7.1。

**四个最有价值的结论**：

1. **优化分两类，必须分开记账**：T1/T5/T1b/M2(C1)/E1/I5/F2 是**模型无关**的（两模型同向受益，可下放到小模型）；
   I1/F1 依赖模型容量（只有 4B 吃得住）。混在一起看，会得出"优化没用"的错误结论。
2. **"改模型输入"几乎总是错的**：C1 首版为省模型力气把原文替换成占位符，导致精度从 0.83 崩到 0.54。
   改成"模型看原文 + 规则事后补漏"后，一举达到 0.961。
3. **指标会骗人，必须核验样本**：同一方案出现过"虚高"（F3 补全版 0.74→0.83，实际是把知识卡原文机械补进答案）
   和"虚低"（判分校准发现规则判分系统性偏严，真实 faq 命中比报告值高 5-8pt）。
   为鉴别"虚高"，又做了 v4 切题性维度——**结论是它也鉴别不了**（详见 §5），这条边界比想象中难划。
4. **确定性短路（F2）是本轮性价比最高的一招，且收益与模型容量负相关**：
   faq 4B 0.798→0.827（+2.9）、1.7B 0.577→0.663（+8.6）。模型越弱，收益越大——因为短路直接把
   "不会答"的问题绕开，用策展过的卡片原文作答（且零生成、零延迟）。

## 四、采纳项：做了什么、为什么有效

### T1 工具直给（取消"模型自选工具"）
- **问题**：基线 A 类成功率 0.20——模型拿 12 个工具 schema 自选，几乎选不对。
- **做法**：意图已经确定工具，直接把工具名和参数 schema 交给模型，只让它填参数。
- **效果**：A 0.20 → **1.00**；同时暴露新问题：C 类（安全）从 1.00 掉到 0.57。
- **教训**：改动会"按下葫芦浮起瓢"，必须有回归检查（后来 D2 就是为此建的）。

### T5 主体与外泄安全策略（代码层兜底）
- **问题**：T1 之后模型会执行"查我妈的余额"这类他人主体查询。
- **做法**：调用前做 policy 校验——主体不是本人、或参数含邮箱/外部通道 → 直接拦截。
- **效果**：C 类 0.57 → **1.00**，且对正常查询零误拦。
- **要点**：**合规底线不能交给模型判断**，必须是确定性代码。

### T1b 参数值级校验
- **问题**：B 类（缺参追问）0.00——模型会把"附近"当城市填进参数。
- **做法**：校验参数值——占位词（附近/那边/这边）、整句回填、以及"中文数字能否覆盖金额"，
  不合法就像用户追问；另外补了中文数字解析（十万 / 三万五）。
- **效果**：B 0.00 → **0.875**（4B 达 1.00）。

### I5 规则前置 OOS 判定（本次最大单点收益）
- **问题**：模型自报的 out_of_scope 极不稳定（四版 prompt 对照下 OOS 拒识在 0.50~0.96 之间乱跳）。
- **做法**：分类后加确定性规则层：第三方 App（微信/支付宝…，带 `微信(?!银行)` 排除）、
  App 故障抱怨、非银行地点、领导联系方式 → 强制 OOS；验证码/诈骗类 → 纠回 security_tips（优先于 OOS 规则）。
- **效果**：intent macro-F1 0.810 → **0.871**（+6.1pt），OOS 0.615 → **0.923**；误拒 0.007。
  联动：tool D 0.80 → 1.00，faq 路由 0.626 → 0.681。
- **为什么收益超预期**：域外样本被错分时，同时污染 OOS 与"落错的那个类"两边的 P/R，纠正后连带上升。

### M2 / C1 规则脱敏（模型无关，双模型双阈达标）
- **问题**：模型分不清"订单号 vs 卡号"，误脱敏行 34/160；漏检 16 个实体。
- **做法**：① 规则识别手机/身份证/卡号（卡号 12-19 位且**过 Luhn**，重叠区段按身份证→手机→卡优先）；
  ② **模型照常看原文**；③ 事后合并实体并过滤模型脏输出（非白名单类型如 `ORDER_NUM`、
  把 `[证件_1]` 当原文的实体）；④ **masked_text 由代码确定性重建**，不信任模型改写文本。
- **效果**：1.7B P 0.832→**0.961**、R 0.947→**0.961**；4B P 0.940→0.938、R 0.943→**0.957**（首次过阈）。
  误脱敏行 34→10，无 PII 误脱敏 19→4。
- **成本**：纯代码，零推理开销，不增加生成轮数。

### E1 intent prompt 精简
- **问题**：intent prompt 渲染 3373 字符，端侧每请求都要 prefill，是 2-3 秒固定开销。
- **做法**：类清单保留（2065 字符不可省），把"易混对"6 组示例（1308 字符）压成 5 行速查 → **2373 字符（-30%）**。
- **效果**：1.7B F1 0.8657、4B F1 0.8991，与完整版**逐项完全一致**。
- **推论（重要）**：I3 当初加示例涨的 3.9pt，本质是"定义修好（I1）"的功劳，示例只是临时拐杖。

### F2 FAQ 确定性短路（本轮新增，性价比最高）
- **问题**：FAQ 命中受限于模型对卡片细节的覆盖；小模型基本答不准（1.7B 仅 0.577）。
- **做法**：问题与卡片信息点的"问题侧二元组覆盖率" ≥0.40 且取 top-2 → **直接返回卡片原文**
  （"根据行内资料：…（以行内公示为准）"），跳过生成；不满足才走原生成路径。
- **与 A1 的本质区别**：A1 是"检索后仍然让模型生成"（剪裁上下文 → 负优化，实测两个模型都降）；
  F2 是"检索后直接作答"（保留全部卡片，零生成、零幻觉）。
- **效果**：4B v3 0.798→**0.827**（首次越过 0.80 阈值）；1.7B v3 0.577→**0.663**（+8.6pt，v2 +10.6pt）。
  短路率约 33%，被短路的行**零生成**，端侧延迟同步下降。
- **验证方法值得复用**：先做离线模拟（`experiments/sim_f2.py`：用现成输出把高置信行的答案替换成卡片原文再重判），
  预测 +4.8pt、实测 +4.8pt **逐点一致**——确定性改动可"先模拟后实跑"，省掉盲跑。
- **副作用**：约 1/5 行的答案由"模型润色"变为"卡片原文"，略啰嗦但更准确（抽检 5 条：4 条更准、1 条稍逊）。

### F0 判分口径 v2 / v3
- **v2（同义归一 + 数字边界 + 长短语模糊）**：v0 用严格子串，把"不收费 vs 不收取费用"判成未命中，导致基线假低。
  效果：基线 faq 命中 0.442 → 重判后 0.471（**口径修正，不是模型进步**——这类数字必须单独标注）。
- **v3（证据化复核，本轮新增）**：在 v2 之上，**只对 v2 判 miss 的信息点**做 LLM 复核，
  且要求裁判从答案中**原样摘录支撑片段**（摘不出即视为未覆盖）——用"证据可回溯"挡住裁判的宽松倾向。
  - 结果：基线 0.471→**0.538**、1.7B 当前 0.500→**0.577**、4B 0.740→**0.798**（距阈值 0.2pt）。
  - 抽检 6 条新增命中：4 条确凿、2 条部分覆盖 → 真实值应视为区间而非点值。
  - **方向性验证**：已知刷分的 F3 首版在 v3 下仍 0.837（高于诚实作答 0.798），证明 v3 没有无差别放水。
  - **暴露的盲区**：判分只问"覆盖没覆盖"，不问"切不切题"，因此"堆资料"式伪命中仍能得分（需 v4）。

### D2 回归护栏 / D3 判分校准
- **D2**：6 组断言（T5/I5/T1b/C1/F1 + 注册表一致性），零模型调用、秒级。
- **D3**：4B 当裁判抽检 30 条 / 35 个信息点，一致率 0.886，**规则偏严 4 次、偏松 0 次**。
  结论：faq 命中率被系统性低估 5-10pt（4B 0.740 的真实值大概率在 0.78-0.82），且不存在"刷分型"漏判。

## 五、否决项：这些坑比成果更值钱

| 方案 | 做法 | 结果 | 为什么失败（可复用教训） |
|---|---|---|---|
| **I4** 阈值扫描 | 离线扫 OOS/置信度阈值 | 指标完全不动 | 模型给出的 confidence 几乎没有区分度（都是 0.9/0.95），**调阈值等于自欺** |
| **A1** 句子级检索 | FAQ 只喂 BM25 top-3 信息点 | 1.7B 0.500→0.481；4B 0.740→0.683 | 知识卡本来只有 3-5 条，剪到 3 条恰好删掉"组合答案"所需条目（转云率 2.2%→3.3%）。**上下文本来就短时，检索是负优化** |
| **F3 首版** 自动补全 | 覆盖率低就从知识卡补原文，最多 2 条 | 0.740→**0.827**（看似达标） | **机械补全**：82/91 条都触发，其中 12% 补错主题（问房贷利率补了活期存款利率）。指标有效（信息确实补给了用户），但**掩盖模型真实能力**，且答案明显啰嗦 |
| **F3 收紧版** | 覆盖率<50% + 词重合≥2 + 只补 1 条 | 0.740→0.760（未达标） | 仍有错配（提现手续费→补行内转账；取款密码→补登录密码）。**字符二元组不足以判断语义相关性** |
| **F0 v4** 切题性判分 | 疑似堆资料的行再问 LLM"是否切题" | 诚实 0.798 不变（零误伤）；但补全版仍 0.817 > 0.798 | **无区分能力**：74/91 行被判"疑似堆资料"，但只有 3 行被判"不切题"——补全版确实回答了问题，只是多说了。**这条边界（补全 vs 刷分）比预想难划，v4 记为 reject** |
| **F4** 跨卡路由兜底 | 当前卡几乎不匹配时切到更匹配的卡 | 双模型与 F2 **完全一致**（4B 0.788/0.827、1.7B 0.606） | 救回的 3 行本来已命中（F2 已覆盖），换卡无增量；且每请求多读 3-5 张卡是纯成本。**门槛教训：初版按"想当然"定 0.45/0.55 → 触发 0 次，门槛必须按实测分布定** |
| **C1 首版** 前置替换 | 先把手机/卡号换成占位符，再喂模型 | P 0.832→**0.543** | ①模型把 `[证件_1]` 当新实体重列（208 误报）；②自创 `ORDER_NUM` 类型；③输入被改写导致姓名识别变差。**不要为省模型的力气改它的输入** |
| **I3** 对抗 few-shot | 加 6 组混淆对示例 | F1 +3.9pt 但 OOS -7.7pt；四版在 0.796~0.843 间震荡 | 已在噪声区（OOS 仅 26 条样本，单条 3.85pt）。且后来证明示例是"定义含糊"的拐杖 |

**共性**：四个失败方案的共同点是——**它们都想绕过"模型理解能力"这个瓶颈**。
凡是绕过（改输入、堆文本、剪上下文），都在某个指标上崩；凡是承认边界（代码兜底、规则前置、
定义修清），都稳。

## 六、核心洞察：模型无关 vs 依赖容量

这是双模型对照最大的收获。判据：**同一改动在两个模型上是否同向、同幅受益**。

| 优化 | 1.7B | 4B | 性质 | 能否下放到小模型 |
|---|---|---|---|---|
| T1 工具直给 | A +80pt | A +80pt | 模型无关 | ✅ |
| T5 安全策略 | C +43pt | C +43pt | 模型无关 | ✅ |
| M2/C1 规则脱敏 | P +12.9 / R +1.4 | P -0.2 / R +1.4 | 模型无关 | ✅ |
| E1 prompt 精简 | 0（持平） | 0（持平） | 模型无关 | ✅ |
| I5 规则 OOS | F1 +6.1 / OOS +15 | F1 +6.7 / OOS +19 | 模型无关 | ✅ |
| **F2 确定性短路** | faq 0.577→0.663（**+8.6**） | faq 0.798→0.827（**+2.9**） | 模型无关，**收益与容量负相关** | ✅ 尤其适合小模型 |
| I1 注册表修复 | F1 **-0.5** | F1 **+0.8** | 依赖容量 | ⚠️ 仅 4B+ |
| F1 FAQ 模板 | 转云 -18pt | 转云 -19pt | 部分无关（拒绝率）+ 部分依赖（命中） | ◐ |
| FAQ 整条链路（I3+F1+I5+F2） | 0.577 | 0.827 | 前段依赖容量，F2 例外 | ◐ |

**结论**：小模型（1.7B）适合走"脱敏 + 意图 + 转云"的极简链路；
只要涉及"读知识卡作答"，1.7B 会卡在 0.5 附近，必须 4B 以上。

## 七、真机验证（一加 Ace 2 / Termux + llama.cpp，1.7B Q8）

**2026-11-11 全量复验**（X3）：同一台机器、同一模型文件，旧 harness（11-03，评测-18）vs 当前 harness（含 C1/E1/F2）。

| 子集 | 11-03 真机（旧） | 11-11 真机（当前） | 变化 | PC 当前 | 结论 |
|---|---|---|---|---|---|
| intent F1 | 0.829 | **0.872** | +4.3pt | 0.866 | 真机略高，差异在噪声 |
| intent acc | 0.873 | 0.886 | +1.3pt | 0.881 | 一致 |
| intent OOS | 0.962 | 0.923 | -3.9pt | 0.923 | 噪声内 |
| faq 命中（v2） | 0.490 | **0.596** | **+10.6pt** | 0.606 | **与 PC 同幅** |
| faq 命中（v3） | — | **0.654** | — | 0.654 | **与 PC 完全相同** |
| mask P | 0.844 | **0.964** | **+12.0pt** | 0.961 | 双阈首达 |
| mask R | 0.943 | **0.954** | +1.1pt | 0.961 | 双阈首达 |
| tool A/B/C/D | 1.0/0.875/1.0/1.0 | 1.0/0.875/1.0/1.0 | 持平 | 1.0/0.875/1.0/1.0 | 平台无关 |

**核心结论：harness 层改动在真机与 PC 上增益一致**——faq +10.6pt（PC 同值）、mask P +12.0pt（PC +12.9pt），
v3 口径下两平台 faq 完全相同（0.654）。说明这些优化不依赖平台，可放心下放到端侧。

**时延**（11-03 真机）：tool 9.2s/轮、mask 9.9s/条、intent 3.8s/条、faq 12s/轮，四子集 **60 分 25 秒**。
11-11 复验：intent+faq+tool 33 分钟、mask 单跑 29 分钟（总耗时与 11-03 相当，F2 省下的生成被网络往返抵消）。

**三条工程约束（血的教训）**：
1. 手机内存余量 ≥ **2GB**（1.7B）/ **3.5GB**（4B），否则 llama-server 会被 OOM 杀掉；
2. 启动必须带 `--parallel 1`（默认 4 slot，KV 内存翻倍）；
3. **端侧评测必须带重试**：本次 mask 首轮 160 条里 **146 条 HTTP 503**（并发槽被占后连锁失败），
   给 `run_eval.py` 加"2 次退避重试"后二轮 **0 错误**。局域网抖动 + 单 slot 服务，瞬态失败是常态。


### 7.1 量化档位对照（X1：Q4_K_M vs Q8_0，同一 harness）

| 模型 | 量化 | 体积 | intent F1 | faq（v3） | faq（v2） |
|---|---|---|---|---|---|
| 1.7B | Q8_0 | 1.8G | 0.8657 | 0.663 | 0.6058 |
| 1.7B | **Q4_K_M** | **1.1G** | 0.8846 | 0.654 | 0.6058 |
| 4B | **Q4_K_M** | **2.4G** | 0.8991 | 0.827 | 0.7885 |
| 4B | Q8_0 | 4.0G | 0.9084 | 0.827 | 0.7981 |

**结论**：
1. **量化损失可忽略**——四个组合的差异全部在 ±2pt 内（即测量噪声内），唯一"方向性"差异（4B-Q8 intent +0.9）不足以支撑多花 1.6G 内存；
2. **量产选 Q4_K_M**：省 40% 内存，对"能否装进手机"是决定性差异，质量无明显代价；
3. **一个重要旁证**：4B-Q8 的 intent F1 = **0.9084**，名义上首次越过 0.90 阈值——
   这印证了 §8 的判断：Q4 的 0.899 与阈值的 0.1pt 差距**确实只是噪声**，不是能力差距。
   但反过来也不能说"Q8 达标了"，因为 0.9pt 的差同样在噪声内。

## 八、未达标项：归因与建议

### 1. 意图 macro-F1：4B 0.899（与阈值差 0.1pt，实为噪声）
- **性质**：噪声级。176 条样本、每类仅 5 条，1pt ≈ 1-2 条样本。
- **X1 提供的旁证**：同一模型换成 Q8_0 后 F1 = **0.9084**（名义过阈），而量化本身不改变语义能力——
  说明 0.899 与 0.90 的差完全在重跑波动范围内（§9 第 9 条）。
- **真正的问题在测试集**：每类 5 条无法支撑 0.90 阈值的判断。
- **建议**：扩充冻结测试集（每类 ≥20 条）后再评估；**不要为此继续调 prompt**。

### 2. FAQ 信息点命中：4B 0.827 已达标；1.7B 0.663 仍差 0.14
- **4B**：v3 口径 0.798 → **0.827**（F2 短路 +2.9pt），**首次越过阈值**。
- **1.7B**：0.577 → **0.663**（+8.6pt），提升更大但仍未达 0.80——剩余缺口是"多信息点组合/卡片未覆盖"类问题，
  短路覆盖不到，小模型也生成不对。
- **4B 剩余 17% 未命中的构成**：① 约 16.5% 的问题被路由到错误知识卡；② 多信息点组合题（短路只返 2 条）；
  ③ 卡片的表述与问题差距大（同义判断不出）。
- **已被证伪的路径**：关键词补全（F3 两版）、句子级检索剪裁（A1）、切题性判分（v4）——都无效或有害。
- **可选路径（按性价比）**：
  a. **跨卡路由兜底**（harness 内，1 天）：当前卡几乎不匹配时切到最匹配卡，直接攻 16.5% 误路由；
  b. 扩充测试集（每类 ≥20 条）并加入多信息点组合题，提升区分度；
  c. **跨文档 RAG**（2-3 天）或 **换 7B/8B**（时延翻倍）：只在需要 0.85+ 时才值得。

## 九、方法论沉淀（可复用清单）

1. **先验证尺子和数据，再跑实验**：规则类方案上线前，用 gold 标签核对覆盖率（C1 因此一次成功）。
2. **不要为省模型的力气去改它的输入**：改输入 = 改任务，模型行为会不可预测地漂移。
3. **合规底线用代码，不用模型**：安全策略、PII 正则、OOS 黑名单都应是确定性判断。
4. **指标异常先看样本**：0.827 和 0.543 都是真的，但都不是能力——一个是刷分，一个是脏输出。
5. **噪声区识别**：当同一方案的多个变体在 ±3pt 内震荡、且样本量小时，说明已到该方法的上限。
6. **示例是定义含糊的拐杖**：当 prompt 里示例越堆越多，先回去修类别定义（I1 之后 E1 立即零损失）。
7. **改动必带回归**：T1 的 C 类掉分、C1 首版的精度崩塌，都是"没有护栏"的代价。
8. **双模型对照是归因的唯一可靠办法**：单模型实验无法区分"harness 好"和"模型强"。
9. **测量误差要先量化，再谈结论**：F4 实验里，同一配置（F2）两次重跑的 `intent_route_ok`
   从 0.835 漂到 0.868、1.7B 从 0.681 漂到 0.747——**差 3 行样本即 3.3pt**，而 F4 完全没碰意图。
   结论：**<3pt 的差异一律视为噪声**；本报告中 intent F1 的 0.1pt、faq 的个别小数点后差异，都不构成结论。
10. **门槛要按实测分布定，不能拍脑袋**：F4 初版门槛取 0.45/0.55（"看着合理"），结果触发 0 次；
    按实测分布（误路由行正确卡分数仅 0.29–0.50）改为 0.40/0.40 才触发 3 次。
11. **确定性改动可以先离线模拟**：F2 用现成输出替换答案重判，预测 +4.8pt、实测 +4.8pt 完全一致，
    省掉一轮盲跑（约 15 分钟）。适用于规则、短路、后处理类方案。
