## 一、方案与改动（T1：intent→tool 直给工具名（取消模型选择工具））

- **动机**：基线 A 类 0.1~0.2，失败样本 action=tool 但 calls=[]，模型根本没输出 <tool_call>； 而注册表里 intent→tool 是一一映射，工具名本不需要模型决定
- **假设**：把"选择工具+格式化调用"降级为"填参数"，1.7B 可胜任
- **改动**：
  - pipeline._route_tool：把该 intent 对应工具（含 schema）直接注入 prompt
  - tool_call.j2 改为"必须调用 {tool_name}，只输出参数 JSON"
  - 代码侧校验参数 JSON 合法后再执行（不合法走一次纠错）
- **预期增益**：{"tool.A": "+40~60pt"}
- **风险**：单一 intent 多工具时需回退原逻辑；参数错误率可能上升（B 类会有反馈）
