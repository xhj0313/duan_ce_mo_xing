# experiments —— 优化实验登记与执行

> 目的：把"改 harness 提指标"变成**可追溯的单变量实验**：每个方案有编号、有假设、有改动记录；
> 每次实验有结果、有判定、有对照组。避免"改了一堆说不清哪个有用"。

## 一、铁律（写死在流程里）

1. **单变量**：一次实验只改一处（一个模板 / 一个注册表字段 / 一处代码）。
   多个方案同时上线 → 分不清收益来源，实验作废。
2. **尺子与系统分离**：判分器口径变更（F0 类）必须单独成实验，且记录 `judge_version`。
   尺子变了导致的分值变化是"测量变化"，**不是系统改进**，不得计入优化收益。
3. **对照组**：每份结果都与 `baseline`（同环境）对比；PC 与真机分开对照，不混用。
4. **速度也是一等指标**：每份记录含 `avg_gen_s`（若可得）。端侧方案若新增生成轮数，
   收益必须扣掉延迟代价。
5. **可复现**：记录 git commit / dirty 文件数 / 模型标签 / endpoint / 数据集版本。

## 二、目录

```
edge-harness-poc/experiments/
├── README.md            # 本文件：流程与铁律
├── schemes.yaml         # 方案登记簿（唯一事实源：id/目标/改动/假设/预期/状态）
├── run_experiment.py    # 执行 + 判分 + 自动登记 + 生成详细文档
├── results.jsonl        # 机器可读的完整实验记录（append-only）
└── results.md           # 人类可读的汇总表（由脚本重新生成，勿手改）

<workspace>/评测记录/     # ★ 档案库：每次实验一份详细文档（体例同 评测-01/02）
├── README.md            # 索引：编号 / 日期 / 环境 / 方案 / 关键指标 / 链接
└── 评测-NN-<env>-<scheme>-<YYYYMMDD>.md
```

**每份详细文档自动包含**：基本信息（方案/环境/模型/端点/commit/dirty）、
方案与改动（从 schemes.yaml 带入动机/假设/改动/预期/风险）、
指标表（本次 vs 同环境基线 + 阈值达标）、**错误模式摘录**（意图最差 5 类、高频混淆对、
tool 失败样本）、子集明细（样本数/错误行/耗时/run_id）、判定与结论、复现命令、原始数据位置。

编号规则：`评测-01/02` 是根目录的手写叙事报告（PC 首轮、真机对比），
基线记录直接链接它们不重复生成；后续实验从 `03` 起自动编号，**一次实验 = 一份文档**。

## 三、标准流程

```bash
# ① 新方案：在 schemes.yaml 登记（status: proposed），写清假设与预期增益
# ② 实现改动（只改一处）
# ③ 跑实验并自动落账（results.jsonl + results.md）+ 生成 评测记录/评测-NN-*.md 详细文档
python experiments/run_experiment.py --scheme T1 --label "intent→tool 直给工具名" \
    --endpoint http://127.0.0.1:8080/v1 --subsets intent,tool --env pc \
    --verdict pending --notes "只改 tool_call.j2 + pipeline 直传工具名"

# ③' 只补/重建文档与索引（改了 schemes.yaml 或补了备注后）
python experiments/run_experiment.py --regen

# ④ 判定并回写 schemes.yaml（status: adopted / rejected / iterating）+ 在 --notes 写结论
# ⑤ 若采纳：git commit，commit message 引用实验ID（例："T1: 直给工具名 (exp 20261102_...)"）
```

> 真机环境把 `--endpoint` 换成设备 IP（如 `http://192.168.104.33:8081/v1`），`--env device`。
> 只分析已有结果不重跑：`--from-run intent=<run_id> faq=<run_id> ...`。
> 查看结果表：`--show`。

## 四、判定规则

| 判定 | 条件 |
|---|---|
| `adopt` | 目标指标提升 ≥ 3pt 且其余指标回退 < 1pt，速度代价可接受 |
| `iterating` | 有提升但未达阈值，或提升 < 3pt（继续迭代该方案） |
| `reject` | 无提升或明显副作用；把原因写进 `notes`，**方案不删除**（保留为知识） |
